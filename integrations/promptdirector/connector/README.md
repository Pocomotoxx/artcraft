# PromptDirector Agent Connector

Provides tools for searching, reading, saving, editing and organizing cases, and supports local Windows, macOS and Linux with Google Chrome. The connector and the extension must both be installed, and Chrome must stay running.

The installer provides configuration adapters for Codex, Claude Code, WorkBuddy, OpenCode, ZCode, the current desktop version of Qoder, and DeepSeek Harness; the Qwen office desktop app offers STDIO configuration import. Local access for Doubao Work is still to be verified, and a network connector is not treated as local support. For the specific versions, installation entries and the difference between acceptance levels, see the [installation guide](INSTALL.en.md). Passing a configuration adapter does not mean each host has completed real-session acceptance.

## Current References and Citations

Original video capture uses the standalone [video component](../docs/VIDEO_COMPONENT.md); install it as prompted in the capture sidebar, with no Agent pairing or preinstalled development tools needed. The component installer ships its own parsing and audio/video merging tools and does not change the registration, pairing or configuration of the Agent.

Select references with multi-select in the case library, and the selection is saved automatically; an external Agent calls `read_workspace_content(part=selection)` directly to read the full references, where the first page may omit the version and continuation pages carry the returned `revision`. Use `read_workspace_context` when only an overview is needed. There is no need to enter the composer, export or send references; an existing composer can be resumed through an explicit page context. The internal model API is not a prerequisite for external calls.

`resolve_reference` accepts the `#pd-reference=…` fragment of a name link, or `promptdirector://reference?v=1&library=…&case=…&asset=…`, verifies the identity and then calls the existing original-text, structure and media interfaces, without visiting the link page. The reference identity contains no keys; a wrong library or wrong media ownership fails explicitly. That this interface is available does not mean drag-and-drop has passed on every host, and cross-app reception is judged by the actual acceptance records. `open_workspace` opens or resumes the case library/composer; `show_case` opens a standalone detail page. Both wait until the live context is readable and then return ready; opening means not yet complete, so keep reading by tabId. Manual selection and drafts are kept.

Dragging a card out uses the case name link, pointing to the whole case; detail images and local videos use the original name link, pointing to the specific asset. Images, videos, documents and other attachments that have a local original also carry the original file as drag data; a video takes the original video and a document takes the original document, and the preview cover is not used as the original. The host must keep the reference in the link or plain text to locate precisely; when only a name is received, a same-name search cannot prove that the drag identity was passed on. The plugin page refuses dragging out when it has no valid library identity, while normal reading can continue.

The rich-text name uses the source web page link of the case, and the locating identity is only in the fragment; without a valid web source, the project home page configured in the extension is used. Clicking the link opens the source or the project home page, and an Agent must call MCP to read. Rich text provides the name link and a hidden original carrier; when an original exists, plain text, URI and DownloadURL follow the original file channel, and only without an original is the named Markdown link used. The receiving script on authorized HTTP(S) web pages converts the original of this plugin into a complete File at the real drop and hands it to the existing upload entry of the site; no new permission is requested and the original is not compressed. After updating the extension, refresh the receiving web page; the site must still support File drop. An Agent that receives only plain text and does not keep rich text cannot be guaranteed to obtain the case reference. The desktop, the web canvas and the Agent must each be accepted by actual reception. Managing the selection/sort state follows existing gestures, and after exiting, all case cards can be dragged out again.

A whole group of creative references can be read page by page with `read_workspace_content(part=selection, expectedRevision=...)`, avoiding a separate round trip per item; `status.workspaceContentParts` probes backend support. `selectedCaseCount` is the number of selected cases and `total` is the number of references expanded per asset. Multiple case library pages that have entered management synchronize the selection state, while ordinary browsing and the selection of other tasks are not switched. Invalid cases or documents are declared through `issues` and `completeness=partial`, and the other references can still be read; `availableCaseCount` is the number of usable cases, and reading does not clear an invalid selection. The list contains the source, the compound member IDs and the number of characters of the original prompt; the complete case structure is still fetched on demand through `read_case_details`.

## Live Collaboration and Review

`capture_workspace` returns a real PNG of the currently visible area of the plugin, the screenshot time, the page identity and the local file path, and MCP returns the image content as well. `tabId` or `surface=library/composer/collector` can be specified; when omitted, only the single visible plugin tab is chosen, and several windows return candidates. It does not activate tabs, steal focus or capture other web pages; the capture sidebar is out of this scope, while a standalone capture tab is available. Switching or refreshing during the screenshot discards that image, to avoid returning the picture of another page. A screenshot does not prove hidden content, originals or save results.

Screenshots follow the existing permissions of Chrome: [captureVisibleTab](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-captureVisibleTab) needs a granted `<all_urls>` or the `activeTab` of the current tab; an MCP request itself does not grant permission. [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) is granted by a user action such as a toolbar action. When unauthorized, `permission_required` is returned, and you can click the toolbar icon on the target plugin tab and retry; no new permission is added and no status text poses as a screenshot.

`read_live_workspace` reads the current context of one case library page, and with multiple pages `tabId` must be specified according to the returned `contexts`. The snapshot contains search/filter/sort, the specific asset, text selection, unsaved edits, creative note drafts and saved feedback, the actual playback state, the review range and the identity of the temporary clip; changes to saved data are signaled by `libraryRevision`, and the complete data is still obtained through the case reading tools. The first connection and reconnection read a snapshot; the context revision/controlRevision cannot be used as a case edit version: for the first read of a case omit expectedRevision, and then continue reading/editing with the revision returned by the case read; afterwards `wait_workspace_changes(tabId, afterRevision, waitMs)` gets ordered changes, waiting at most 15 seconds. With `reset=true`, continue from the new snapshot returned and do not join expired events.

`control_workspace` locates cases/assets, sets the reference selection, plays/pauses/seeks/loops and switches review on the same page. Put the `controlRevision` of the context into `expectedRevision` and provide a unique `requestId`; the change stream continues with `revision`; after a manual operation an expired command is rejected, and unsaved edits cannot be discarded automatically. Search candidates are shown in the conversation of the Agent, page operations reuse existing interactions, and no extra candidate layout is added. Turning on range looping plays directly; open_temporary can replace the current temporary clip when it explicitly switches clips, and close_temporary closes it. Unsaved case edits still need handling. Changing the action, file or version requires a new requestId, and only a retry with the same parameters keeps the original ID. The receipt distinguishes actual execution from failure, and `foreground` says whether the page is in the foreground; `state=executed` and `snapshot` mean the action finished and the business state afterwards, and do not claim visual layout acceptance; normal calls reuse the receipt snapshot, and a re-read happens only after the user keeps operating. A kept request can replay its receipt; when the automatic history expires, only old commands are rejected, without executing again, and continued review is not restricted.

The Review button at the top of the detail collapses the body and recommendations and reuses the current media; exiting restores the original layout. The local player supports seeking and ranges, and when an embedded source player cannot be controlled this is stated explicitly, with no pretense of frame-level precision. A temporary clip can be passed in by the Agent or imported through Add → Review local clip; there is no permanent entry beside the logo. The Agent uses `control_workspace(action=open_temporary, file={path,mimeType})` to pass in an explicitly specified file without storing it first; a temporary upload without feedback is organized along the existing lifecycle; originals and attached frames linked to saved feedback are kept and cannot be discarded as idle transfers. Call `read_review_media` with the `temporary.id` of the context, and the connector reads it completely, checks the SHA-256 and returns the local file path. After changing the clip or closing, the old identity becomes invalid. The entry for reading the current original is given by the mediaRead of the context; when temporary=null use read_media to read the library case, and do not guess a temporary ID. Clicking the Save to library icon of the temporary review saves the current original, saved feedback and attached frames to the current project together; when the user delegates saving, the Agent can also use control_workspace(action=save_temporary,temporaryId=current temporary ID). Saving follows the same original/version/receipt service, shows saved on success, and repeated clicks/retries do not add copies.

Current live collaboration covers case library pages; the full references of the composer still follow the existing `read_workspace_content(source=page)`. The interface provides snapshots and waiting for changes, and does not declare MCP resource subscriptions or waking the model automatically when any host is idle. `status.workspaceSyncVersion=6` means the backend has loaded; after saving unfinished edits, reload the extension and refresh the page, and then the host refreshes the tools.

Video detail and temporary review share one playback timeline, and the in point, out point and selected range are shown directly on this line; reviewing does not switch cases. Creative notes, standalone screenshots, clearing in/out points and in point/out point/loop are on the same row. A note defaults to the current playback time, and the full range can be chosen explicitly with the range icon; clearing the in/out points also turns off looping. The note window can be dragged and by default avoids the top and bottom toolbars; the refresh-time button next to save re-reads the actual playback position, keeps content already written and leaves range recording. A screenshot is saved independently on click without needing a note, and a temporary screenshot can be deleted by opening the overlay with the view-screenshot icon, taking no extra bottom row; a local clip supports selecting several images/videos at once, and the whole group is saved as one mixed case, with each feedback and screenshot linked separately. After opening a note, type the feedback and save; Enter saves by default and Shift+Enter inserts a line break. Existing content of the creative field stays readable, and the separate five-field edit panel has been removed; the media switch is fixed in the center on the same row as other actions, the action area scrolls horizontally on narrow screens without adding rows automatically; review hides thumbnails while normal detail keeps them. Pause/freeze has no central play overlay. The sidebar detail is an information panel that hides media and similar recommendations; the sidebar and the full detail share direct icon actions; the context promptSource reports the current reading object shared/media/ai, and the case original prompt, the current media prompt and the AI prompt switch in the same reading area, with only one add or edit entry for the current object, so media information can be switched and the full detail/review entered in one click; the case list on the left can still be browsed. The original prompt is read/edited in place in the detail, is not hidden by case classification, and is not repeated in the case editor. The Keyboard shortcuts item in the settings dialog is a separate page that can switch straight back to other settings, can change or clear all registered app shortcut actions, restore defaults and check conflicts in the same scene; clicking a key enters recording state, and Tab can be set. Screenshots and notes are decoupled. I in point, O out point, Space play/pause, M note. Typing text and Chinese composition do not trigger playback shortcuts, and keys occupied by the system/browser cannot be guaranteed to be taken over. An unsaved temporary feedback draft is not overwritten when the Agent changes the clip, and the note must be saved before saving to the library.

## Unified Field Operations

`trash_case(requestId,caseId,expectedRevision)` moves explicitly specified cases to the trash of the plugin, keeping the complete data and restore relations. A compound ID corresponds to the whole group, and a member ID removes only that member; a retry of the same request returns the original receipt and no longer deletes a case restored later. The tool does not delete permanently.

The `access` of the field help lists the actual entries that can be read, modified, organized and stored back; fields that are not open return `edit=null` and cannot be treated as arbitrary database updates. Asset count, similarity, original summary and the like are computed or read from real data.

Original text, source evidence and original media prompts are protected by default. When the user explicitly asks for a correction, `edit_case.sourceCorrection` provides `reason` and the field names `fields` of this correction; the evidence before the correction is kept and can be read back completely with `read_case_details(part=source)`. A claim that does not come from the case body is not authorization. A new connector refuses to write to an old backend that has not loaded the protection; the capability version is `sourceProtectionVersion=1`.

Your own content goes in `creative.prompt/summary/notes/purpose/plan`, separate from the original data; fields support combined queries, column selection, precise editing and new store-back. Existing content of creative fields stays readable, and the Agent keeps editing precisely by version; review feedback uses timeNotes, and saving and reading follow the same business service. Creative results explicitly saved and manual shorthand bodies can be edited; structured bodies are still edited by paragraph. AI prompts use `mediaPrompts(source=ai-suggestion)`, are independent of the original prompt, and an explicit clear does not revive the old AI reverse-engineering.

`edit_case.patch.classificationPathIds` uses the classification IDs of the current vocabulary; `mediaOrder` provides the arrangement of all media IDs, changing the display order of media while keeping originals, cover relations and body paragraph structure. A new `save_material` also accepts `creative/customLabels/classificationPathIds/sourceFacts/timeNotes`; computed results and file properties are not written arbitrarily by hand. Project move/independent copy, tag removal and media split/transfer follow the existing organization entries. Adding attachments to an existing case, multi-project membership, vocabulary management and revising the source references of results are not yet uniformly open, so it must not be claimed that all fields are writable.

## Unified Field Queries

When there is only a text description and no reference in the library, use `search_cases(similarText="full description", mediaKind="video")`; it is exclusive with `similarTo` and can be combined with the existing scope and field filters. It reuses local prompt similarity, does not create a temporary case and does not call a model, and word relevance is not equal to visual recognition. After the Agent finishes the analysis itself, it keeps writing back through the existing external analysis batch; the connector provides no tool for starting paid model analysis of the plugin.

When fields are unknown, call `describe_case_query` to get field names, types, supported operations, scopes and the actual engagement metrics in the library. Reuse known definitions within the same session; there is no need to consult the help every time. Queries uniformly use `search_cases`, and the internal composer and the CLI follow the same rules; `status.caseQueryVersion=1` declares that the backend has loaded. An old backend reports an explicit error: save unfinished edits, reload the extension, and then refresh the host tools.

`where` accepts `{field,op,value}`, `{all:[conditions]}`, `{any:[conditions]}`, `{not:condition}`, or `{scope,where:condition}`. The scopes `member/source/media/label/project/classification` mean that the same relation record satisfies the sub-condition; for example, for a video of a certain author in a compound that has an original prompt, nest media inside the same member and do not join words of another author. Unknown fields and unsupported operations fail directly. The top-level provider/authorHandle limits the members that take part in source/member field queries and engagement sorting, and logical case-count fields still count the whole case.

```json
{
  "provider": "x",
  "authorHandle": "@example",
  "where": {
    "all": [
      {"field": "source.capturedAt", "op": "between", "value": ["2026-10-01T00:00:00Z", "2026-10-31T23:59:59Z"]},
      {"field": "project.ancestorIds", "op": "eq", "value": "ID of the project already read"},
      {"field": "prompt.original", "op": "exists", "value": true},
      {"field": "mediaCount", "op": "gte", "value": 3}
    ]
  },
  "orderBy": [{"field": "source.engagement.bookmarks", "direction": "desc", "reduce": "max"}],
  "select": ["title", "source.url", "mediaCount"]
}
```

Authors, projects, dates, counts and engagement metrics are passed in by the task and the field discovery results, and the example is not a default product rule. `select` returns only the specified fields and caseId, multi-valued fields return arrays, and complete text is not cut into a summary; when a single large text exceeds the message budget it fails explicitly, and `read_case` should be used to page through the same-version text. The default is still a short candidate, and no recognition of the picture is claimed if images were not viewed.

`orderBy` sorts after all matching, supports several fields, always puts missing last and breaks ties by caseId; multi-valued fields must specify min/max, and engagement sorting and numeric statistics must be limited to a platform by the top-level provider, with no automatic adding up of several posts. A 0 in a condition is a known value, and missing is handled with exists=false; ne does not treat missing as not equal to 0.

`groupBy` returns groups/groupTotal; several fields of the same source, asset, tag, project or classification are grouped by the same relation record, each group counts the same case only once, and same-domain statistics also use only the relation records of that group. `aggregates` supports count (no field passed), known/missing, and numeric sum/avg/min/max; missing is not filled with 0, and numeric statistics give known/missing at the same time. Statistics apply to the whole match set and are independent of the number on this page; group sorting uses the group field of orderBy, group.count or the aggregate statistic name (single values do not use reduce), and cannot be mixed with case select/old sort; groups and cases both continue reading with offset/limit/revision, and later pages must carry expectedRevision and keep the query parameters.

`similarTo:{"caseId":"known reference ID"}` compares by the full prompt by default. With `mediaKind:"video"` specified, only video prompts are compared, and a reference containing images and videos can also find pure video cases; without a type, comparison follows the media domain of the reference. Per-asset original prompts take priority, and when missing the saved AI prompt is used with the source marked. The `excerpt` of a default candidate returns a prompt preview, `similarity.promptEvidence` marks the source and the full character count, and coverage information is attached to the `referencePrompt` of the reference (sources, excerpt, excerptOnly, characters); the summary follows the 240-character preview budget of existing candidates, ranking still uses the full text, and the full text is read normally when needed. Omitting select keeps media, source, summary and the matching basis.

The score measures text overlap in the library; it is not a probability of visual similarity and does not understand the creative dimension that matters most to the user this time. For example, two transitions in the same film may score high because the title and crew text are the same; when the specific technique of a candidate does not match the task, it cannot be recommended on score alone. The Agent first understands the goal of the user and uses the existing reference and candidate summaries to judge the common points/key differences. Explicit content constraints can merge `query`/`alternatives` or `where` with `similarTo` in one search; for example, to find similar seamless transitions combine `query:"seamless transition"`, and when broader exploration is needed, not all tags are forced to agree. There is no need to add fixed multiple rounds of visual checks; read further only when the existing text is insufficient.

The Agent chooses limit according to the needs of the task and the quality of candidates and judges whether to continue; deliver once the evidence is enough, without a fixed number of calls or reading all pages. Follow up only on candidates missing prompts, where `hasPrompt:false` can limit the follow-up range (having an original prompt or a stored AI prompt counts as true, subject to the mediaKind/source/duration conditions); when the prompt is enough, covers and videos are not read by default, except when the user asks for visual verification. A score of 0 means no known word overlap, and it must not be treated as similar just to fill a count. This is currently local word similarity and does not guarantee cross-language semantic matching; necessary keyword variants can be put into alternatives in one go.

An explicit `method:"local"` keeps the existing exploration rules of the plugin; palette/tags and local are still compared in the same complete media domain, and the recommendation algorithm inside the plugin is unchanged. It returns the reason, fallback, per-item values and similarityCoverage, where missing is null and 0 is known dissimilar; the coverage count is the comparison domain of the current library, and other query conditions filter further. Not having read the original does not mean visual recognition. Use palette.colors for exact color values and the palette method for color similarity.

The full names have the `promptdirector_` prefix. Creation is done by the Agent, and these tools do not call a model additionally. Recoverable deletion is only for objects explicitly specified by the user; permanent deletion or automatic whole-library analysis is not provided. Whether a tool is available is determined by the tool list of the current connector and the `status` receipt of the plugin; new editing capabilities require updating both ends at the same time.

Original downloads are chunked according to the transfer direction of Chrome native messaging and the current working memory, keeping the complete file and the digest check. When storing back the same local image, video or audio, the extension can reuse an original in the library whose actual bytes have been verified, avoiding repeated upload and storage; changed files still go through the normal upload. Even if attachments in the same batch have identical content, the identities needed for different per-file prompts are kept. After an update, reload the extension and reconnect the MCP service of the Agent; an already started service may still use the old code.

The download directory of the connector holds temporary copies that can be obtained again: the first reception verifies the complete digest, and within the same process the verification result is reused while the file identity, size and modification time are unchanged, but the original is still checked against the current library each time. Registered copies idle for 7 consecutive days are reclaimed under the existing temporary resource policy; historical files being transferred, edited or unregistered, and leftover occupancy markers are not deleted automatically. This is an idle lifecycle, not a library capacity limit; exports you need to keep long-term should be saved to your own working directory.

Connection waiting follows the existing 30-second budget; writes and original reads allow two processing stages, at most 60 seconds, and change waiting adds the requested wait time. A write timeout means the completion state is unknown and does not resubmit automatically; first check with the original request ID to avoid saving twice.

External batch analysis: the analysis is done by the host and the plugin receives the results. First read the case versions and the originals actually needed; register `instruction` and `items:[{caseId,expectedRevision,assets:[]}]` with `manage_analysis_batch(action:"create")`, and the returned `batchId` is the creation request ID. For text analysis `assets=[]`; for visual analysis provide `{assetId,sha256,coverage}` for each item, where the digest comes from `read_media` and coverage honestly states the whole video, sampled frames or a specific range. A large list can be registered in batches with `add` and ended with `seal`; each case is registered once per batch, and multiple assets go in the assets of that case.

`read_analysis_batch` gives each item `attemptId`, the input version and the batch `epoch`. After the host finishes an item, submit `result` or `error` with `submit_analysis_result`, which are mutually exclusive. result accepts `tags:[{g,t?}]`, `mediaPrompts:[{assetId,text}]`, `timeNotes:[{assetId,startMs,endMs?,text}]`, and the following complete results shared with the plugin:

- `imageAnalyses:[{assetId,reconstructionPrompt,tags}]`: per-image reverse engineering and 1–6 tags, without fabricating descriptions, coordinates or the ten-dimension structure.
- `videoAnalyses:[{assetId,reconstructionPrompt,tags,uncertainties,analysisScope}]`: complete video reverse engineering, 4–8 visual tags and uncertainties; `analysisScope` is `visual` (picture) or `video` (audio and picture), and the actual sampled frames/time range still follow the registered `coverage`. `finishReason=external_result` in the saved record means the host submitted the result and is not the finish reason of a model request initiated by the plugin.
- `visualSetAnalyses:[{assetIds,imageRoles,sharedVisualSystem,differences,continuity,compositionRules,reusablePrompt}]`: multi-image relations and creative summary; every image must already have a valid independent analysis consistent with the current original, `imageRoles` exactly covers the specified assets, and the per-image results can be saved first and then summarized within the same item.

The same asset cannot submit both `mediaPrompts` and a complete image/video reverse engineering. The tag g is read from `part:"taxonomy"`; abnormal, duplicate, overlong or over-limit tags reject the whole item and are not silently trimmed. Image prompts and time notes must be inside registered assets; tags are appended and manual relations are kept, prompts are written only with the AI source, and time notes are only added. A reverse-engineering result that already has a different AI prompt or a manual edit must be checked separately and go through `edit_case`, and is not replaced in batch. A complete free-form analysis report is saved with `save_material` and linked to the source; this interface does not accept arbitrary low-level fields.

Complete image results are read with `read_case_details(part:"media")`, and video and whole-group results with `part:"annotations"`; `inputEvidence` keeps the input case version, the original digest, the viewing range and the attempt identity. `part:"analysis_coverage"` lists the stored analysis per media and the unknown ranges; a missing range is `null` and the whole video cannot be inferred. `verification:"verified_at_save"` only says it was verified at save time, and `currentBytesVerified:false` states explicitly that this metadata read did not re-verify the original. This list is not a whole-library picture search index. When a whole group of media is split/transferred, the complete report stays with the assets; when only part is split, the source report is kept as invalidated history and no subset is passed off as a complete group analysis. Backup/sharing keeps the structure and the source range, and when an imported media ID conflicts, the analysis references are adjusted accordingly. `status.analysisResultVersion=2` and `analysisResultFields` declare the current backend capability; after a source/runtime update, check Chrome reload and the rediscovery of host tools separately.

A result submission returns the final receipt of a single item; `ok:true` means the receipt was recorded, and `item.state` must be checked for `saved`. A failed item carries the specific reason, and `partial` must not be reported as a success of the whole batch. When the case, relations or original change, the whole item fails and the old result is not written. Metadata, the case edit and the receipt are committed together; a retry of the same request with the same parameters does not add tags or notes again.

Cancel with `manage_analysis_batch(action:"cancel",epoch:...)`; ordinary progress changes do not block cancellation. Succeeded items are kept and later results of the old epoch are rejected. It only stops the plugin from receiving, and the host must stop the model or script requests itself. `resume` only resumes receiving and does not analyze automatically; after re-checking the current epoch, handle the unfinished items, and an old result must not be submitted directly under another ID. Failed items use `retry` with a re-verified single-item input, and are redone after obtaining a new attemptId; the old attempt and the failed result can still be read. Except for create/cancel, management operations must carry the latest expectedRevision. All write operations have a unique requestId.

After forgetting the batch ID or reconnecting, first find it with `list_analysis_batches` by `query` (requirement or ID)/`status`, then check with `read_analysis_batch`. The list takes only task summaries and does not load case or result bodies; `instructionExcerpt` follows the 240-character length of the search summary, and `instructionTruncated` means the complete requirement must be read from the batch. The list is sorted by latest update with 24 items per page; later pages carry `revision` as `expectedRevision` and keep the filter, and after a change re-read the first page. Only external batches of the current library are listed, excluding internal model tasks. Continued checking needs no `get_task`. items is a compact page, results can be read as complete JSON with `part:"result",caseId:...` by nextOffset, later pages carry expectedRevision; taxonomy continuation pages also carry contentRevision as expectedContentRevision. A batch not yet sealed is collecting, and one sealed but with items still unsubmitted is awaiting_results; these states do not mean the plugin is running a model. Task receipts belong to the run records of the current browser library and are not included in the portable backup; save a complete report you need to keep long-term as a case.

Batch write-back can use `submit_analysis_results`, passing `requestId`, `batchId`, `epoch` and `items:[{caseId,attemptId,model?,result or error}]`. At most one page of 24 items each time, consistent with read paging; single-item calls are still available. Each page reads the current library only once and submits once, and the per-item input version and original checks are kept. Cases in the same page must not repeat; unregistered, expired attempts or format errors reject the whole page without a partial submission. Case conflicts and analysis content errors within valid attempts are recorded as failures per item and the rest are saved; check the returned `items[].state/error`. The whole page can be retried with the original request, and an existing receipt does not overwrite later manual edits. Cancellation takes effect between pages, and a page already in saving finishes first; the larger the page, the longer cancellation waiting and original verification may take, so there is no need to delay existing results just to fill a page.

The internal composer uses the same batch service and permission checks, and the image tool `use_case_images` returns the digest of delivered originals; it redelivers when an original changes and reuses when unchanged. Internal native video input has not yet reached the analysis capability of external hosts such as FFmpeg, and consistency of the interface must not be taken as consistency of all model capabilities. The existing batch analysis UI and background tasks of the plugin are not replaced, and whether the new tools are available is determined by the actual backend status and the refresh of host tools.

Skill reading: first `list_skills`, then `read_skill` as needed, with later pages pinning `expectedRevision`. A kept version can be read with `versionId`. In the file list, `current` is the files generated from the body and references of the version read, and `package` is the package saved as it was (including scripts, extra frontmatter and binary attachments); the main document of the original package may predate manual text edits. Plain Markdown without a description keeps the original text, and `currentFileHasFrontmatter=false` means the generated file lacks complete portable metadata. `packageFileScope=unrecorded` means the old version recorded no files, and current scripts cannot replace them. File continuation reads carry `expectedHash`; use `download_skill_file` to obtain the complete file and organize the host directory by `relativePath`. The plugin does not run scripts, and a successful download does not mean runtime verification.

Skill writing: use `save_skill` after the user delegates. To create, provide the call name `callName` and `skillMarkdown`, or provide a complete package `files:[{path:"/absolute/path/SKILL.md",packagePath:"SKILL.md"}, ...]`. Only explicitly specified files are uploaded, and there is no need to zip by hand. A whole package follows `SKILL.md`, and another copy of the body, references, description or portable ID must not be passed at the same time; when updating, the `name` inside the package must match the `portableId` of the original Skill. An update needs `skillId` and the `expectedRevision` already read; a body-only update that omits `references` keeps the references, and only an explicit `[]` clears them. The connector first checks the backend capability and `status.skillPackageLimits`, verifies the actually declared boundaries before uploading, and rejects an old backend that lacks complete package capability; there is currently no file-count or package-size quota. Files are verified by digest and then linked to the version and the request receipt; if saving fails, the staging is kept and files that may already be referenced by a commit are not deleted.

The two save methods are as follows; a `requestId` is generated for each new operation, and updates add `skillId/expectedRevision`. The file package mode no longer carries inline body text or references.

```json
{"requestId":"new-inline-request","callName":"Camera movement method","skillMarkdown":"# Camera movement method\nComplete body","references":[{"path":"references/source.md","markdown":"Complete source text","runtime":false}]}
```

```json
{"requestId":"new-package-request","files":[{"path":"/absolute/path/SKILL.md","packagePath":"SKILL.md"},{"path":"/absolute/path/source.md","packagePath":"references/source.md"},{"path":"/absolute/path/frames.py","packagePath":"scripts/frames.py"}]}
```

A reference with `runtime:true` enters the reference snapshot and model context when the Skill is applied inside the plugin; `false` is still saved completely and can be read on demand. Choose according to whether the reference needs to stay in the model context, and do not rewrite it automatically because the text is long. References inside a package follow the existing import rules.

The `quotaPolicy` of `status.skillPackageLimits` explains that the product has no fixed package quota; `MAX_SAFE_INTEGER` in the retained `maxFileCount/maxFileBytes/maxArchiveBytes` values is the boundary of safe integer representation and must not be interpreted as unlimited for every call. `maxTextBytes` is the parsing budget of the current body and Markdown references, which the connector checks before uploading and the backend still checks finally. File chunk length and total package size are different boundaries. The complete UTF-8 JSON envelope of an inline request is limited by the 1 MiB message limit from the local program toward Chrome; files go in chunks, and when a single message is exceeded use file paths, without compressing or cutting the original text. [Chrome native messaging protocol](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging#native-messaging-protocol).

Use `restore_skill` to restore a historical version, which by default restores the body, references and recorded files together. When the old version has no file record, a complete restore is refused; use `mode:"text"` only when the user explicitly asks to restore the text only, in which case the current package files are kept. Historical files follow the existing version retention limit of the plugin; backup, sync and cleanup recognize originals still referenced by kept versions. A newly added file snapshot cannot make up for historical scripts unknown before the upgrade, and it is not guaranteed that an older plugin version rewriting again will still keep these new fields.

Skill writing and restoring return the final receipt directly, without `get_task`. A unique `requestId` is generated for each operation, and on a disconnect the same parameters reuse the same ID; `replayed` is a historical result, and read back again when the current state must be confirmed. The internal composer still keeps the draft viewing and saving entries. For daily use both the plugin and the connector need updating, and the host may need to refresh tools or start a new session.

Original reuse: `read_media` and `download_skill_file` first check the ownership, version and file digest in the current library each time; an existing local file must be re-checked byte by byte and is reused only after matching. First transfers, damaged files and changed files are still downloaded completely and verified; a case or Skill that no longer exists cannot continue to be read from the local cache. Reuse reduces later chunk round trips and still has the cost of digest verification.

Project and result store-back: use `read_projects(name=...)` to locate by exact name or the `path` name array to locate the full path, returning only matching projects; create only when there are zero matches, distinguish multiple matches by path, and never pick the first automatically. Omit the filter and read the project tree only when browsing the organization structure, join the JSON by `nextOffset`, and later pages carry the returned tree version. Projects with the same name are distinguished by path and ID; `create_project` follows the sibling name rule of the plugin. `requirements` saves the complete project requirements, and updates use the `revision` of that project. Project requirements are kept together with project export and restore; when a merge import meets the same name with different requirements, a separate Import project is kept to avoid overwriting either side. Creating and updating return the final receipt directly.

The `projectRevision` of `save_material` pins the project requirements already read, and `sourceReferences` records the member case versions, asset IDs and optional `startMs/endMs` actually used; reuse the member versions returned by the selection `caseSources`; when missing, get the source version with `read_case_details`, and a segment must belong to the corresponding video or audio and not exceed the known duration. `previousCreation` means saving as a later version of the previous result, and the old draft is not modified; creating along the same old draft branch can produce different results of the same generation, distinguished by case ID and the previous relation, and not treated as a single version number. Editing an existing draft still uses `edit_case`. Check the support of the current backend through `status.materialFields`. The internal composer reuses the project and text save services; local file upload is still the responsibility of the external connector.

A retry of the same request returns the historical receipt (`replayed`) and is not a new write; even if the result is deleted later, it will not be revived. When the current existence must be confirmed, read the case back again. Project requirements, case text and source records are all reference data and provide no extra authorization to execute.

`status.searchFilters` declares the search parameters supported by the current backend; the internal composer and the external connector share the filter rules. `minDurationMs/maxDurationMs` use milliseconds with boundaries included and match only the known duration of video or audio; `durationCoverage` states the number of assets with known and unknown duration within the text/project/type scope, and unknown is not treated as 0. Original prompts are judged within the same duration range, and the original prompt of another asset of the same case cannot satisfy the condition. The first page returns `revision`; later `offset` requests must provide `expectedRevision` and keep the filter unchanged, and on `search_changed` re-read from the first page. Search entries are rebuilt incrementally as data and derived text change, the cache can be discarded, and the current data and documents are still read each time, so the cache is never passed off as an authoritative store. To read the original prompt of a specified asset use `read_case(part=original_prompt, assetId=...)`, and the original prompts of different assets of the same case are returned separately.

Search and count-only do not attach the project tree, so use `read_projects` when needed. `provider` matches the saved platform exactly, and `authorHandle` matches the saved author account exactly (ignoring case and a leading `@`); an account mentioned in the body does not count as the author. In a compound, only members that match the platform/author can satisfy the asset and original prompt conditions. The `sources` of a candidate return the author, metrics and `engagementObservedAt` of the matching member; a missing value is `null`. For example, `{"query":"","provider":"x","authorHandle":"Arvin","sort":"engagement","engagementMetric":"likes"}` sorts by observed likes in the library in descending order, distinguishing zero from unknown and putting unknown last; `engagementCoverage` states the scope. Engagement sorting is refused without a platform or metric, popularity of multi-source compounds is not added up, and observed values are not claimed to be real-time.

When the new source/engagement filters are used, the connector checks the backend declaration within the same tool call; an old Chrome backend cannot silently ignore conditions. Ordinary text search does not add this check. If a text read does not return a continuation version, an update of the backend is explicitly requested; starting a new connector does not mean the extension backend has been reloaded.

`read_case` returns only text, identity and continuation information; use `read_case_details` on demand for the complete media/source/project structure. `status.caseTextReadVersion=2` declares continuation protection: obtain `revision` on the first page, then use it as `expectedRevision` later while keeping `caseId/part/assetId`; on `case_text_changed` re-read from the first page and do not join old text. This version only pins the text read and the object, and editing still uses the edit version of `read_case_details`. `body` is the case body, and `original_prompt` organizes the original prompt by source evidence; the two may be the same or different, so do not mechanically read all parts repeatedly for the same goal.

Before editing, read the object and version with `read_case_details`. `content` is paged JSON, later pages carry `expectedRevision`, and it is parsed after reading to the end by `nextOffset`. Writes carry `expectedRevision` and a unique `requestId`; when the version changes, check again and never overwrite an edit the user has just made. Retrying the same request returns the original receipt, and the case update and the receipt are committed together. Editing and organizing return the final result directly without `get_task`. Merely querying or reading grants no permission to modify, and the Agent should act within the range delegated by the user.

Media splitting follows the original project, keeping original references, covers, per-media prompts and time notes without copying large files. The body and source of the new case must be provided explicitly and cannot reuse the text of the original case; `textBlockIds` can move original paragraphs that have been checked. A project move removes the original membership, while an independent copy keeps two cases that can be edited separately.

`organize_case(action=combine_cases)` creates a compound with the first `caseId/expectedRevision` and the `additionalCases` listed in order, and needs `title`. A compound keeps the original project membership of each member and does not move or copy members across projects automatically. `split_compound` carries the compound ID and version already read to restore independent members, without deleting cases. `edit_case` can change the compound name, tags and the content-image cover of a member; the body/media of a member still must specify the member. For an ordinary case, `patch.coverVisualId` can set an existing image (including a video cover), and `null` restores the automatic cover; a cover is not treated as the original video. Check the actual fields and actions of the backend through `status.caseOperationFeatures`. The operations do not create a library backup or permanently delete originals.

Images, videos, multi-image and mixed attachments are stored with `save_material(files=...)`, and a standalone cover can also be saved as an image. Uploading a new cover file for an existing case, automatic screenshots at a specified video time, and directly starting analysis with the built-in model of the plugin are not yet open. After an external Agent reads the originals, it can write back complete image, video and multi-image relation analyses through the batch interface above; free-form reports are saved with `save_material` and linked to the source.

`read_media` returns a local file path. The Agent must have the corresponding image, video or document reading capability to analyze the file. Only downloading the original does not mean visual analysis is done. When there is no local original or linked-file authorization an explicit error is reported, and a thumbnail is not used as the original.

Store-back uses the existing file format recognition, document extraction, media storage and project membership logic. `files[].originalPrompt` is bound to that attachment. `sourceCaseIds` saves a snapshot of the source title, URL and the case ID under the identity of the original library; the source snapshot in a share package does not represent a clickable link in the library of the receiver. Markdown image references are not downloaded automatically, and the original image must also be provided as an attachment. A long body can be submitted through `bodyFile`; the inline body length is limited by the single-message capacity of the protocol, and files use chunks, so there is no need to shorten the body or compress originals.

File import follows the existing format and capacity checks of the plugin. `forceImport` is only for imports after the user agrees to the large-image risk reported by the plugin, and does not skip the checks for insufficient space, damage or format. The browser is still limited by the actually available storage space.

## Shared Capabilities of CLI and MCP

An Agent that supports MCP should call the tools directly first. When the host caches an old tool list or supports only the command line, you can run `node call.mjs list` in the connector directory to discover tools; call for example `node call.mjs read_workspace_context`, with parameters passed as JSON through standard input. The CLI calls the same MCP service, so validation, pairing, permissions, versions and receipts are consistent, and no separate set of command logic is maintained. It does not read or send the chat of the host automatically.

## One-Sentence Connection

Click Copy connection instruction in the Agent connection section of the Chrome plugin settings and paste it to the current Agent. It checks the environment, installs, configures and verifies according to the [unified installation guide](INSTALL.en.md); when needed the user enables the connection in the browser.

The unified entry is `node connector/setup.mjs plan|connect|verify`. The installer directly supports the user-level configuration of Codex, Claude Code and WorkBuddy, and other local stdio MCP hosts use `generic` to output the standard configuration. The local bridge includes installation paths for Google Chrome on Windows, macOS and Linux. Windows uses the user-level registry, a private directory and named pipes; native Windows Node.js is required. Pure cloud access is not part of this flow. The isolated environments of different desktop workbenches must be checked separately, and compatibility must not be inferred from the brand alone.

Backups are kept before configuration is written, and damaged files or other connections with the same name are not overwritten. Verification confirms that the connector works through an actual MCP handshake and a case query, and afterwards the current Agent session still has to call the tools before the user can be declared connected. The detailed steps and installation dependencies are carried out by the Agent according to INSTALL.en.md, and the user does not need to edit configuration files.

The default connection directory is `.promptdirector` under the home directory of the current user. `PROMPTDIRECTOR_CONNECTOR_HOME` can specify another private user directory, and the installer and the Agent configuration must be consistent. Multiple Chrome profiles each have a pairing number; `PROMPTDIRECTOR_INSTANCE` can specify an instance explicitly for different Agents, and if unspecified the pairing selection is used.

The run code of the local connector is copied to a stable private directory and does not depend on the development directory staying in place. At installation, a launch path that exists, is executable and resolves to the same current Node is preferred (including symbolic links), to avoid recording a resolved version directory; when none is found the current executable path is kept, and another version in PATH is not substituted. After Node is removed, the launch link becomes invalid or the path changes, rerun the installer to update the entry. After upgrading the connector, the plugin must disconnect and enable the connection again. The macOS Unix socket path has a system length limit, and a directory that is too long prompts for a shorter path. The `verify` offline diagnosis only checks the own files of the connector and does not infer the browser or extension switch state from them.

## Data and Connection

`connector_access_denied` means that the runtime environment of the current Agent does not allow access to the local connection, so it cannot be used to conclude that the plugin is offline or to require re-pairing. Check the local access permission of the host and verify the same connection in an authorized environment; do not handle it by disabling security protection. `connector_offline` means the connection does not exist, was refused or has been dropped.

The connection uses Chrome Native Messaging with Windows named pipes or a user-private Unix socket, and has no network listening port. Chrome verifies the extension identity, and the connector then verifies the instance number and the local key. MCP exposes only explicit business operations, provides no arbitrary internal messages or arbitrary script execution entry, and returns no AI service keys.

Original copies are stored in `files` of the connection directory, and transfer records and task receipts are kept in the local storage of the extension. Disconnecting only stops new requests, and tasks already submitted continue to be processed; tasks left unfinished because Chrome was closed are reported as interrupted in the next query. After a network or client timeout, query with the original request ID, and losing the response must not be taken as not stored.

Files waiting to be submitted are staged before storage and enter a case only after the integrity check passes. Unfinished files are not cleaned up automatically, to avoid wrongly deleting the originals of a disconnected task. Assets already stored are managed by the original library.

Whether material obtained by the Agent is sent to a model or other services depends on the host settings and the instructions of the user. This data flow should be understood before enabling it for the first time. The tools do not bypass restrictions of the browser, the host or websites; when login or manual verification is needed, the actual error is returned.

## Release Package

Download and unpack `PromptDirector-version-Agent-Connector.zip` from the [Agent connector download page](https://github.com/wchao6891/PromptDirector/releases/tag/agent-connector-v0.5.0), and have the Agent run the installation and connection check in the unpacked folder according to `INSTALL.en.md`. In the package, `extension/manifest.json` is used to verify the plugin identity, and `case-operation-specs.js` and `project-operation-specs.js` are the shared tool definitions; for the actual extension use `PromptDirector-version.zip` to upgrade. Connector 0.5.0 supports viewing, editing, organizing, reference handoff and the CLI, and adds recoverable deletion, text similarity search for unstored text and workspace page screenshots; the package does not include Node.js, and the Agent checks and prepares a compatible runtime according to the unified installation guide.

The normal path for reading and saving: pin the selection and read the complete content in the same pass → locate the project by name/path → save. The selection `originalText` is kept completely once; `referenceTextParts` contain, in order, strings and references pointing to `originalText` or `referenceSources[index].text`, and the source `textSource=originalText` works the same way. `media` returns the owning case, the original role, the cover ID and known size/duration; unknown values are not fabricated. The source version covers the cases and the organization relations, and paging still refuses changes.

`save_material` waits at most 15 seconds on the original task (half of the existing 30-second connection timeout, leaving margin for submission and transfer), and a fast save returns the final state directly; on timeout the original task state is returned, continue with `get_task` and do not submit again. The completion receipt contains the body length/SHA-256, the current project version, the source and the result version; these are persistent receipts at submission time, and independent acceptance still requires reading back. When an old backend does not support waiting, it still returns processing and does not pose as complete. When the client loses the receipt, the request identity is kept, and later manual edits and deletions are not overwritten by a replay.

To read the complete selection directly use `read_workspace_content(part=selection)`, where the first page may omit `expectedRevision`; the connector reads the selection version and then the body in the same call, avoiding extra waiting between two rounds of tool calls of the model. The data is still checked by version, and a selection that changed between the two reads is not silently mixed. Continuation pages or single reads must carry the version. Use `read_workspace_context` only when a list overview is needed.

`organize_case(action=remove_tags)` accepts `customLabels` (manual tag names) and `nodeIds` (classification tag IDs), and at least one must be specified. When operating on a compound, members are included, only the relations of the selected cases are removed, and the vocabulary, originals and analyses are kept. It still needs the `expectedRevision` already read and a unique `requestId`; it returns `updatedCount` and `canUndoFacetUpdate`, and can be undone in the plugin under Categories and tags → Tag navigation → Undo and restore.

## Everyday Conversation and On-Demand Reading

The connection handshake provides brief delivery and call guidance, the tools provide readable titles, and successful result data is marked as intended for the assistant; whether the host collapses tool details is decided by the host. By default tools, IDs or internal parameters are not announced step by step; failures and necessary decisions still need explaining, and complete prompts, original text and creative content are not shortened. Evidence is expanded only when the user explicitly asks for diagnostics.

When `read_case_details` needs several parts at once, pass `parts:["overview","source","media"]`, which returns one shared revision and a paged JSON object. It is exclusive with the single-part `part`; continuation pages keep parts and expectedRevision, and are parsed after joining completely. The service builds the required parts in a single data read, without re-reading the whole library or computing analysis coverage that was not requested. When only one part is read, keep using part. To find a new screenshot of the current case, update media first, locate by derivedFromAssetId/frameTimeMs/capturedAt, and then read_media; do not scan local directories.

Search is done by the calling Agent generating cross-language synonymous expressions, covering at least the system language of the user in `status.searchGuidance` and English, merged in one go with `query`/`alternatives`. Multiple words form an intersection and synonymous queries form a union; the plugin does not need to call a paid translation API, and the user is not asked to translate.

### Original Text Locating and Batch Capture Tasks

Capture completeness: summary.platform gives the actual adaptation capability, and candidates[].supplements lists the comment sources and partial; use read_capture(part=supplement,candidateId,supplementId) to call the comment expansion collector of the plugin, and save the frozen full text with textSources according to the returned selector. partial is still incomplete, and the originalVerification after saving is the actual read-back result of storage; duplicate cannot prove that new full text was saved.

`read_capture(part="page")` contains the locating facts of the current selection, the visible code area and the dialog. `read_capture(part="source", selector)` freezes the complete original text of the specified web region and returns a new revision; the candidates of `update_capture` can use `textSources:[{selector,target:"text" or "prompt"}]` to adopt the original text directly, including the original code whitespace. Paged reading by the Agent does not mean the original text is shortened, and it cannot be called fully read before it is read to the end. When `status.captureReadParts` of an old backend has no `source`, the new capability is not assumed to be available.

`update_capture.task` can register `objective/outcome/candidateIds/state`, and a batch save must select all the actual candidates declared; when specific case IDs or the corresponding save receipts are missing, the preview is kept. `create_project` returns a persistent project receipt directly, without polling `get_task`. Media can provide a web `url` or the `localTransferId` of a prepared original, and the plugin verifies the file identity and type; screenshots uploaded only for the conversation are not saved automatically. The internal capture assistant and external MCP calls run along the same preview and storage rules.
