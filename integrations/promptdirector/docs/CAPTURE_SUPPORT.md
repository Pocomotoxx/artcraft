# Web Capture

Open the extension on the work, post or article you want to save, click Web capture, check the body text and media, and then save. Selections, picked images, the clipboard and screenshots can keep supplementing the current draft. Ordinary capture, manual supplementing and saving do not call AI.

When a case is already selected, Pick content is appended to that case from the very first time, keeping the existing body, prompts and selection; a screenshot is also saved as a newly added image. Selecting the same image again merges the usable sources, prefers the original, and does not add the image twice; undo can go back to before the supplement. When no case is selected or several cases are selected, manually picked content is added to the preview independently, keeping the original candidates and selection.

Generic capture and site adapters share the original-first rule: an original explicitly provided by the page takes precedence over the display image, and X photos use the original address. When the public download of the original fails, the web session is tried within the authorized scope; only if it still fails is a usable preview used, and the downgrade is stated in the save receipt. When the site provides no accessible original, the preview is never called the original; a manual screenshot keeps the pixels of the selected picture.

Click the assistant icon at the top of the capture page to ask directly How do I capture this? or How do I save to a project?, or describe what to capture. Asking about usage does not force a scan or a save; after capture is explicitly requested, the body text, media, project selection and the save button appear directly in the conversation. You can click save, or say explicitly save to a certain project; when no new project is specified, the current manual selection is kept. The save result can open the case directly, and duplicate content also applies the explicitly specified project.

The assistant reuses the creative planning model already configured in the AI service; the input box shows the model, and the model button explains possible API costs; opening the assistant does not call a model. Replies support streaming display and Markdown. The attachment button can add local images, videos or documents, refreshing keeps the prepared attachments and selection, and saving follows the original storage flow of ordinary capture. When an ordinary scan fails, the assistant can read the actual body text and media links of the page to fill gaps; a model that supports image input can also read the currently visible page screenshot or the image originals in the preview. A screenshot or cover does not mean the original video was obtained, and the current capture conversation does not directly understand video content.

Closing the assistant keeps the background task, and reopening reads the original task without resending the model request; Stop cancels the assistant alone and keeps the preview. After switching pages or changing the preview manually, the assistant result is kept and does not overwrite the current content; it can be retrieved when you return to the original page with the preview unchanged. A partial save reports what is missing explicitly, and keeps existing results and the entry to continue capturing. After the browser background is interrupted, paid requests are not resent automatically, and the unfinished state is reported explicitly.

New conversation clears the currently visible chat and keeps unsaved previews and cases already stored. When the page changes, the corresponding session is switched automatically, and the preview and project selection of the old page are kept and can be continued after returning; during an ordinary save or attachment read, the current operation finishes before the view is switched.

Export conversation diagnostics next to the page title uses the same JSON format and file naming as the composer; the capture part additionally contains the multi-turn records of each page and before the new conversation, the model and the actual tool steps, selections, save receipts and failure reasons. Before export, the included content is explained; service keys and media files are not included. It downloads only on click and adds no model requests or periodic checks. Clearing the visible chat does not delete these local diagnostic records.

An external Agent uses the same set of preview, read, supplement, select and save tools through MCP. When the plugin recognizes too little, it can read the web page itself within what the host and the site allow, add the actual body text and media addresses back into the preview; originals already downloaded are saved through the data store-back tool. A model summary is not treated as the original text, and browser permissions, login or site refusals are not bypassed.

`read_capture(part="page")` reads the capture snapshot by default; for a retry or when the page has just loaded content, use `refresh=true` to re-read the actual page from the paging start, and later paging and selection use the returned version. `part="screenshot"` and `part="image"` return actual images for the Agent to understand, where for images the candidate and media must be specified explicitly; a missing original is not replaced by another image. A screenshot is limited to the capture page currently visible, and switching pages or navigating refuses the read.

Unfinished previews are kept continuously; previews already stored are organized under the automatic history budget. History organization does not delete saved cases, originals or task receipts.

Articles keep the order of text and media; a work description does not automatically serve as the original prompt. Per-image prompts explicitly provided by the source are saved together with the corresponding assets. A video cover is only for preview and does not mean the video has been saved or can be played.

## Save Granularity for Ordinary Web Pages

For web pages without a dedicated adapter, the capture preview can choose Save as a whole, Group by page section or One case per media. Grouping by page section uses the heading levels of the body text and the media order and does not require prompts to appear; when no explicit boundary is found, the whole content is kept. Splitting by media lists images, animated images or videos as separate cases, and source variants of the same asset and video covers are not counted as another case.

Switching the grouping uses the content already obtained and does not rescan. In the preview, a group can be split by media, selected groups can be merged, or adjustments can be undone; body text and attachments that cannot be clearly attributed stay in Ungrouped content for selection. Shared introductions do not automatically become the original prompt of each media. These operations happen before saving, and ordinary cases already stored do not offer this split entry for now.

Identically named text in a table of contents does not replace section titles; when the same fragment appears in several sections, each section keeps its own reference, and saving by media keeps one independent case.

Ordinary capture reads only the current page by default and does not wait for secondary details. After a readable detail entry is detected, the preview shows Capture detail info, unticked by default; only when the user ticks it are same-site detail links explicitly provided by media cards and declarative GET detail entries read. Cancelling detail reading keeps the basic results and manual selection, and supplements already completed can be undone. After checking that the main media of the returned page belongs to that card, the original text such as title, introduction and credits and the source link are kept and saved with the owning media group. Reading progress follows the capture feedback; when a detail fails, the content already captured is kept and the missing items are listed, and on permission refusal, rate limiting or timeout the remaining detail requests are stopped. Forms are not submitted automatically, page scripts are not executed and links are not traversed recursively; details that open only through opaque scripts, are cross-site or need extra identity verification may still need manual selection to supplement.

The ordinary web preview shows the original media first, and uses a single-frame screenshot only if the source fails to load. Visible cards in the library play the original file after recognizing an animation container, and an old static thumbnail does not replace an animated image; static images keep using cached thumbnails.

Ordinary capture keeps lazily displayed images in the body that already have a real address and a reasonable size; hidden templates, collapsed areas and unloaded carousels may still need to be expanded on the original page before rescanning or manual supplement. Dedicated sites keep using their own extraction and article grouping rules.

## Batch Capture from Lists

On a list page, switch to list mode and enter the target count. Capture keeps scrolling or paging and merges duplicate entries; the actual result depends on what the page can provide. Before saving, the project, content type and tags can be selected uniformly, and entries are checked one by one and stored separately. When the scan ends, is stopped or there is no more content, the actual number obtained is shown, and cases not obtained are not made up.

An ordinary web page can first have one example picked manually, and then list batch capture is used. The batch scope follows the chosen set and content level: when only images or text are picked, it is not automatically expanded to the whole card, and no other similar set on the page is captured. A manually picked template applies only to the current page; when this page has fewer than the target count, the actual results are kept, and other pages must be picked again. After refreshing, navigating or when the chosen structure becomes invalid, a prompt asks to pick again.

Explicit detail links in manually picked content can also be used for Capture detail info. When the video provided by a detail corresponds to the cover of the current card, the complete video can replace the thumbnail preview while keeping the selected state; the original prompt explicitly provided by the page is saved with the corresponding video. Videos in recommendation areas or whose ownership cannot be verified are not added to the current case.

## Videos and Save Results

- The complete video file is downloaded and saved by default. Web playback addresses, covers and segmented resources are not counted as the original being saved successfully; a parsing or download failure keeps the item for retry together with the specific reason.
- Turning on Save online playback only in Settings → General → Video capture lets you skip the original download actively to save space; this setting is off by default, and existing cases and originals are unchanged. Standalone online playback keeps the original work address and a separate playback address; segmented HLS keeps using the player bundled with the extension.
- The local video component reuses the local communication registration of the connector and does not depend on the Agent connection switch. Parsing uses the local yt-dlp, separated audio and video are merged with FFmpeg, and no paid parsing website is called; the login, region and access restrictions of the chosen website still apply.
- Online videos still depend on source availability. When login expires, a link expires, rate limiting applies or playback is forbidden, the problem is shown and you can return to the original work and capture again; a cover or a web embed is never used to pose as video playback.
- When the case body or some media has been saved, unfinished capture items are kept for retry and the failure reason is shown; after all complete, the capture preview is cleared. Supplementary text and images already saved are cleared from the draft, and a retry saves the rest to the same case.
- Everyday use does not require uninstalling the extension or rebuilding the case library. The local version updates the program in the original directory, and existing cases and media stay in the current browser.
